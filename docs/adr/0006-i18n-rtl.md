# ADR 0006 — Internationalization and RTL (English + Hebrew from day one)

**Date:** 2026-10-12
**Status:** Accepted

## Context
Audience includes Hebrew speakers; full i18n is a day-one requirement.
Hebrew is right-to-left.

## Decision
- All UI strings and region names come from locale files keyed by id — no
  hardcoded text.
- Ship **English + Hebrew**; architecture supports adding any locale.
- `dir="rtl"` mirrors UI chrome for Hebrew. **The SVG map never flips** —
  geography stays correct; only menus/text/layout mirror.
- Region-name translations are data, filled and coverage-checked by the
  `add-language` skill.

## Consequences
- RTL must be considered in every UI component.
- A separation rule (chrome flips, map does not) must be enforced in the
  renderer.
- Locale coverage is a quality gate before a language ships.
